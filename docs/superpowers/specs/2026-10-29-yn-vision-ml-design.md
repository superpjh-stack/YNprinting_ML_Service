# 와이엔프린팅 비전 머신러닝 서비스 상세 설계

작성일: 2026-10-29. 상태: 범위 승인 반영, 상세 설계 검토본. 구현·학습은 아직 실행하지 않았다.

## 1. 목적과 범위

사용자가 승인한 두 서비스는 인쇄판 문안 정합성 검사와 목형 칼날 불량검사다. 데이터수집 → 정제 → 피처 엔지니어링 → 모델 적용/학습 → 성능측정 순서로 재현 가능한 업무 흐름을 제공한다. 검사 담당자는 이미지와 원본을 등록하고 정답을 검수하며, 분석 담당자는 데이터셋 버전을 고정해 모델을 비교한다. 현장 작업자는 결함 위치와 근거를 보고 최종 판정한다.

첫 구현은 로컬에서 동작하는 React/TypeScript 화면, FastAPI API, 별도 Python 학습 작업자, SQLite 메타데이터와 파일 저장소로 구성한다. 이후 PostgreSQL 및 S3로 전환할 수 있도록 저장 계층을 분리한다. AWS 배포·MES 실연결·카메라 SDK 연동은 실제 접속 정보와 설치 조건 확인 후 진행한다. 설비 자동 제어, 조색 최적화, LSTM 생산 예측은 이번 두 서비스 범위에 포함하지 않는다.

## 2. 근거와 현재 데이터

근거 문서는 제공된 분석설계+중간점검의 SF-AD1~AD3, SF-TD1~TD5 문서, 착수보고 PPTX, 고객 질문서, 시스템구성도 HTML, IA 기능정리 HTML이다. 전체 원본 경로와 SHA-256은 `docs/evidence/source-inventory.json`에 기록한다. 원본 파일은 수정하지 않는다.

착수보고 슬라이드 12는 문안 OCR·원본 비교·YOLOv8 결함 검출, 13은 목형 형상 비교·YOLOv8·Autoencoder, 14는 모델 검증 목표, 15는 데이터 수집 요건을 제시한다. 기술 명칭은 후보 모델이며, 성능 검증 전 확정 모델로 취급하지 않는다.

프로젝트 폴더에서 PNG 237개, JPG 30개를 확인했다. 267개 이미지의 파일 해시는 모두 달랐다. 시각적 유사 중복은 아직 검사하지 않았다. PDF 56개에는 업무 문서도 포함되므로 전부 원본 시안으로 계산하지 않는다. 불량 제출 목록 Excel은 헤더를 포함해 62행이며 인덱스·폴더명·원본 개수·불량사진 개수·자재코드·품명·불량사유 열을 가진다. 일부 사유는 흰색 얼룩·기포·이물질·인쇄불량이다.

이 목록은 폴더 수준의 약한 라벨이다. 사진별 문안 오류 정답, 정상 실촬영본, 결함 좌표, 검수자, LOT, 촬영 시각은 별도 검증해야 한다. 목형 데이터는 별도 식별·검수가 완료되지 않았다. 디렉터리 이름이나 PDF 존재만으로 학습 가능 판정을 내리지 않는다. 완제품 라벨 사진과 실제 인쇄판 촬영본의 도메인 차이도 기록한다.

## 3. 구현 접근 비교와 선택

- 권장: 원본 비교·OCR·형상 분석 기준모델을 먼저 구현하고 라벨이 확보된 데이터로 학습 모델을 비교한다. 데이터 부족을 드러내면서 단계별 결과를 검증하기 쉽다.
- 검출 모델 단독: 풍부한 위치 라벨을 요구하며 문자 내용 오류와 신규 시안 대응을 따로 해결해야 한다.
- 정상 기반 이상탐지 단독: 정상 표본 확보에 유리하지만 불량 유형과 문자 정합성 설명이 제한된다.

첫 방식을 채택한다. 정상 기반 이상탐지는 검증 가능한 정상 데이터가 있을 때 추가 후보로 사용한다. 기준모델 실행, 사전학습 모델 추론, 회사 데이터로 재학습한 모델을 UI와 보고서에서 구분한다.

## 4. 데이터수집과 스키마

수집 단위는 검사 이미지 한 장이며, 원본 시안/목형 기준 이미지와 연결한다. 필수 공통 필드는 sample_id, service_type(plate/die), source_file_id, sha256, product_id, group_id, reference_id, capture_domain, label_status다. LOT·설비·촬영시각·작업지시번호는 수집 가능한 경우 저장하며 미확인은 null로 유지한다.

문안 전용 필드: artwork_revision, plate_id, reference_text, text_regions. 목형 전용 필드: mold_id, reference_revision, camera_calibration_id. 라벨은 OK/NG/미검수, defect_type, bbox 또는 polygon, 정답 문자열, 검수자·시각·버전으로 구성한다. 정상 이미지의 빈 결함 목록과 라벨 미등록은 다르다.

원본 파일, 참조 이미지, 라벨 이력, 데이터셋, 데이터셋 구성원, 정제 실행, 피처 실행, 학습 실행, 모델, 평가, 검사 결과, 감사 로그를 각각 저장한다. 원본·라벨·모델·예측 사이의 ID 연결을 보존한다. 파일 가져오기는 업로드 또는 관리자 지정 서버 경로만 지원하며 임의 경로 접근은 허용하지 않는다.

## 5. 정제와 라벨 검수

파일 형식·디코딩·크기·중복·회전·흐림·과노출·참조 누락을 검사한다. 원본은 보존하고 정제본과 변환 행렬을 별도 저장한다. 해시 중복과 유사 중복 후보는 그룹화하며 자동 삭제하지 않는다. PDF는 페이지와 렌더 해상도를 기록해 이미지로 변환한다.

폴더와 Excel 행은 정확 일치 및 정규화된 이름으로 매칭하고 미매칭·다중 매칭을 검토 큐에 둔다. 폴더의 불량 사유는 제안값일 뿐, 사람이 서비스·유형·좌표를 확인하기 전에는 정답으로 승격하지 않는다. 문안/칼날 분류에 맞지 않는 외관 불량은 별도 유형으로 남기고 해당 평가에서 제외 사유를 기록한다.

정제 상태는 통과/검토 필요/격리다. 참조 부재·정합 실패·판독 실패는 OK가 아니라 판정 불가다. 실패율도 전체 처리 결과에 포함한다.

## 6. 피처 엔지니어링과 모델

### 문안 서비스

기준 시안과 촬영본의 기하 정합, 문자 영역 추출, OCR 문자열과 신뢰도, 문자열 편집거리, 영역별 차이맵을 만든다. 중요한 숫자·단위·기호는 정규화로 제거하지 않는다. OCR 언어·전처리·정합 파라미터 버전을 저장한다. 문자 정답과 비교하는 기준모델을 만들고, 위치 라벨이 충분하면 번짐·누락·점 결함 검출 모델을 학습한다. 학습 데이터 증강은 train에만 적용하며 문자 내용을 무의미하게 바꾸는 변환은 제외한다.

### 목형 서비스

기준과 촬영본 정합, 칼날 관심영역, 윤곽·에지, 연결 끊김, 기준 대비 위치 편차를 추출한다. 물리 단위 보정이 없으면 편차는 픽셀로만 표기한다. 형상 비교 기준모델, 라벨 기반 검출 모델, 정상 기반 이상탐지 후보를 비교한다. 정상 기반 모델은 검수된 정상 train만 학습한다. 2D 사진으로 관찰 불가능한 마모는 모델로 확인 가능하다고 주장하지 않는다.

공통적으로 변환 파라미터는 train에서만 결정하고 validation에서 임계값을 선택한다. 모델 아티팩트에는 데이터셋 해시·코드 버전·설정·시드·전처리·의존성·클래스 목록을 함께 저장한다.

## 7. 데이터 분할과 학습 실행 조건

문안은 동일 시안 및 유사 개정판, 목형은 동일 목형을 기본 그룹으로 묶는다. 동일 LOT·중복 이미지·동일 원본에서 만든 crop도 분할을 넘지 않게 연결한다. 누수 방지를 우선해 연결된 표본은 같은 그룹으로 배정한다. 70/15/15를 목표 비율로 사용하되 그룹 크기로 실제 비율은 달라질 수 있다.

검증·시험에 정상과 대상 불량 유형이 존재하는지 확인한다. 불가능하면 평가 불충분으로 표시하며 정확도 목표 통과를 선언하지 않는다. 데이터가 적으면 train 내부 그룹 교차검증을 사용할 수 있지만 독립 시험 결과와 구분한다. 최신 현장 기간의 별도 시험으로 실제 적용성을 검증한다.

학습 시작 조건: 파일 해석 가능, 서비스 분류 및 정답 검수 완료, 필요한 참조 연결, 누수 없는 분할, 선택한 모델이 요구하는 라벨 존재. 부족하면 필요한 표본과 라벨 목록을 반환하고 작업을 시작하지 않는다. 임의 합성 라벨로 실제 성능을 채우지 않는다. 데모 데이터는 파이프라인 시험에만 사용한다.

## 8. 성능측정과 목표 충돌

| 항목 | 착수보고 슬라이드 14 | 분석설계에서 확인된 기준 | 적용 방식 |
|---|---|---|---|
| 문안 정합성 정확도 | 80% 이상 | 95% 이상 | 두 기준 프로필 병기 |
| OCR 문자 인식 | 85% 이상 | 95% 이상 | 두 기준 프로필 병기 |
| 칼날 탐지 정확도 | 85% 이상 | 최종 검수 기준 확인 필요 | 착수 기준으로 개발 비교 |
| 불량 Recall | 85% 이상 | 학습 적합성 Recall 85%와 구분 | 서비스·유형별 보고 |
| 이상탐지 F1 | 0.85 이상 | 지표 단위 확인 필요 | 이미지 단위와 객체 단위 분리 |

위 수치는 개발 비교 프로필이며 계약 검수 기준을 자동 확정하지 않는다. 최종 검수 판정은 기준 프로필 승인 전 보류한다. 실측값·표본수·분할 ID·분모·오류 사례를 항상 표시한다.

이미지 수준 Accuracy=(TP+TN)/N, Precision=TP/(TP+FP), Recall=TP/(TP+FN), F1을 제공한다. 분모가 0이면 null과 계산 불가 사유를 반환한다. 클래스별 지표 및 혼동행렬을 제공하고 부족한 클래스는 명시한다. 객체 검출은 IoU 기준과 mAP를 따로 보고해 이미지 정확도와 혼동하지 않는다.

OCR은 정답 문자열 기준 CER=(대체+삭제+삽입)/정답 문자수와 정확 대응 문자 비율을 함께 산출한다. 1-CER을 정확 문자 비율과 동일시하지 않는다. 문자 정규화 규칙과 정답 없는 샘플 수를 기록한다. 평균값 외에 그룹 기반 부트스트랩 신뢰구간을 제공하며 그룹 수가 적으면 불확실성을 표시한다.

챔피언은 validation에서 Recall 제약을 만족한 후보 중 F1이 높은 모델로 선택하고, 동률이면 CPU 추론시간을 비교한다. 제약을 만족하는 후보가 없으면 후보 모델로 유지한다. 고정 test는 선택 완료 후 한 번 평가하고 결과에 맞춰 재튜닝하지 않는다. 추론 지연은 대상 CPU에서 p50/p95와 이미지 크기를 함께 측정한다.

사업 KPI는 별도로 불량수량/생산량×100(5%→4%), 수주확정~출하완료 평균시간(24h→20h)을 계산한다. 모델 Accuracy와 혼합하지 않으며 현재 자료로 KPI 개선을 입증했다고 표시하지 않는다.

## 9. 화면과 API 경계

좌측에서 문안/목형 서비스를 선택하고 상단에 수집·정제·피처·학습·평가 단계를 둔다. 각 단계에 입력 버전, 성공/실패 수, 다음 단계 진행 가능 여부와 사유를 표시한다. 라벨 검수는 원본·촬영본·결함 영역을 나란히 보여준다. 모델 비교는 실제 실행 결과만 표시한다. 검사 화면은 정상 후보/이상 후보/판정 불가와 작업자 최종 판정을 분리한다.

주요 API: POST /api/imports, GET /api/samples, PUT /api/samples/{id}/labels, POST /api/datasets, POST /api/cleaning-runs, POST /api/feature-runs, POST /api/training-runs, GET /api/jobs/{id}, POST /api/evaluations, POST /api/inspections, GET /api/models. 데이터셋·피처·학습 요청은 버전 ID를 참조하며 클라이언트가 임의 파일 경로나 실행 코드를 전달하지 않는다.

오래 걸리는 작업은 queued/running/succeeded/failed/cancelled 상태와 로그를 가진다. 단계 실행은 중복 요청 키로 멱등성을 보장한다. 실패한 작업은 모델 등록을 하지 않는다. 목록에는 안정된 정렬과 페이지 제한을 적용한다. 모델 미설치·데이터 미충족은 구체적인 오류와 준비 방법을 표시한다.

## 10. 보안·운영·검증

로컬 개발은 loopback으로 바인딩한다. 공유 운영 전 관리자/검수자/조회자 권한, 인증, 감사 로그, 백업 복원 검증을 완료한다. 업로드는 경로 순회·압축 폭탄·과대 이미지 검사를 적용한다. 원본·이미지·민감 문안은 외부 AI로 자동 전송하지 않는다. 모델 파일은 신뢰된 등록 경로에서만 로드한다. MES 초기 연계는 읽기 전용으로 설계하고 결과 쓰기는 별도 계약으로 분리한다.

검증 항목: 원본 보존, 중복 및 참조 검증, 좌표 변환 정확성, 라벨 변경 이력, train/test 그룹 비중복, train 전용 전처리 적합, 없는 모델로 예측 성공을 반환하지 않음, 무라벨 학습 차단, 지표 0분모 처리, 판독 실패 보고, 학습-추론 전처리 일치, 작업 재실행 재현성. 백엔드 테스트와 프런트엔드 빌드, 실제 브라우저의 수집→평가 흐름을 확인한다.

## 11. 구현 인수 기준 및 외부 의존성

첫 산출물은 수집/검수/분할/기준모델/학습 어댑터/평가를 실행 가능한 형태로 제공한다. 실제 데이터 학습 성립 여부는 준비도 보고서에 따라 결정한다. 두 서비스 각각 데이터 준비 상태와 실행 가능한 단계가 보여야 하며 미학습 서비스를 성공한 것처럼 표시하지 않는다.

현장 담당자 확인이 필요한 항목은 정상 및 목형 사진 확보, 이미지별 정답 검수 담당, 원본 개정판 매핑, 카메라 해상도·조명·배율, 최종 검수 지표다. 이 정보가 없어도 수집·정제·라벨링·평가 기반 구현은 가능하다. 실제 목형 학습과 최종 성능 보증은 해당 데이터 및 조건 확보 후 진행한다.

다음 절차는 상세 설계 검토 후 구현 계획 작성이다. 현재 세션에 writing-plans 스킬이 발견되지 않았으므로 구현 계획 단계에서 해당 지침을 대체할 진행 방식 확인이 필요하다.
